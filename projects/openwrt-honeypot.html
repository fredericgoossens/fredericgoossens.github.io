Stock router firmware is a black box: no shell, no scripting, no visibility into who is knocking. So I flashed my ASUS RT-AX53U with OpenWRT and turned it into a small sentry - a hardened firewall plus a lightweight honeypot that watches for scanners and emails me when someone touches a port they shouldn’t.

Firmware

OpenWrt wiki: ASUS RT-AX53U / RT-AX1800U - note from the wiki: the RT-AX1800 and RT-AX1800U (non-U) are not the same device - do not flash non-U devices!

Firewall baseline

  • Disabled 80/tcp (no web UI exposure)
  • Disabled 22/tcp (no SSH exposure)

The honeypot

The idea is to create a very lightweight honeypot that sends email alerts:

  • socat to open fake ports
  • Logging of connection attempts to a file
  • Email alerts with msmtp

1. Install packages

opkg update
opkg install netcat msmtp msmtp-mta coreutils-base64 ca-bundle bind-dig bind-tools socat

2. Configure SMTP to send alerts

root@openwrt:~# vi /etc/msmtprc
defaults
auth on
tls on
tls_trust_file /etc/ssl/certs/ca-certificates.crt
logfile /tmp/msmtp.log

account default
host smtp.gmail.com
port 587
from <YOUR_GMAIL_ADDRESS>
user <YOUR_GMAIL_ADDRESS>
password <generated_App_Password - https://myaccount.google.com/apppasswords>
  • I’m using Gmail’s SMTP relay for the alerts.
  • The app password is generated in the Google account settings - never reuse the account password.

3. Fake listeners with logging (start-honeypot.sh)

#!/bin/sh

LOGDIR="/tmp/honeypot"
mkdir -p "$LOGDIR"
DETAILLOG="$LOGDIR/all_connections.log"
touch "$DETAILLOG"

# Start dummy listener that just logs connections
start_listener() {
    PORT=$1

    socat TCP-LISTEN:$PORT,reuseaddr,fork \
    SYSTEM:'IP=$SOCAT_PEERADDR
        HOSTNAME=$(host $IP 2>/dev/null | awk '\''/pointer/ {sub(/\.$/, "", $NF); print $NF}'\'')
        [ -z "$HOSTNAME" ] && echo "[$(date)] - Unknown Connection To Port '"$PORT"'" >> '"$DETAILLOG"' && exit 0

        MAC=$(ip neigh show "$IP" | awk '\''/lladdr/ {print $5}'\'' | head -n1)
        VENDOR=$(wget -qO- "https://api.macvendors.com/$MAC")

        echo "[$(date)] - $IP [$HOSTNAME] - $MAC [$VENDOR] - Connection To Port '"$PORT"'" >> '"$DETAILLOG"'
    ' &
}

# Start listeners on common ports
echo "Starting minimal honeypot..."
start_listener 21
start_listener 23
start_listener 2121
start_listener 3306
start_listener 6379
start_listener 8080
start_listener 8888
start_listener 445
start_listener 2222
start_listener 3389

echo "Honeypot running. Logging to:"
echo "- Individual port logs: $LOGDIR/port_[PORT].log"
echo "- Combined log: $DETAILLOG"
echo ""
echo "Active listeners:"
netstat -tulpn | grep 0.0.0.0 | grep tcp

Each listener runs socat with a shell action: for every connection it resolves the peer’s hostname, looks up the MAC address in the neighbor table and its vendor, and appends a timestamped line to a combined log.

4. Email alerts (smtp-alerts-monitor.sh)

This script tails the log file and emails me for every new entry:

#!/bin/sh

# Configuration
LOGFILE="/tmp/honeypot/all_connections.log"
EMAIL_RECIPIENT="<YOUR_RECIPIENT_ADDRESS>"
SUBJECT_PREFIX="Honeypot Alert"
CHECK_INTERVAL=5  # Seconds between checks

# Check if msmtp is installed
if ! which msmtp >/dev/null 2>&1; then
    echo "Error: msmtp not found. Please install msmtp."
    exit 1
fi

# Check if log file exists
if [ ! -f "$LOGFILE" ]; then
    echo "Error: Log file $LOGFILE does not exist."
    exit 1
fi

echo "Starting log file monitor for $LOGFILE..."
echo "Sending notifications to $EMAIL_RECIPIENT"

# Get initial line count
last_lines=$(wc -l < "$LOGFILE")

while true; do
    # Get current line count
    current_lines=$(wc -l < "$LOGFILE")

    # If new lines are added, process them
    if [ "$current_lines" -gt "$last_lines" ]; then
        # Extract new lines (from last_lines + 1 to current_lines)
        new_lines=$(tail -n +$((last_lines + 1)) "$LOGFILE")

        # Process each new line
        echo "$new_lines" | while read line; do
            # Skip empty lines
            [ -z "$line" ] && continue

            # Format the email with headers and body
            EMAIL_BODY="To: $EMAIL_RECIPIENT\nSubject: $SUBJECT_PREFIX\n\n$line"

            # Send the email using msmtp
            echo -e "$EMAIL_BODY" | msmtp "$EMAIL_RECIPIENT"
            if [ $? -eq 0 ]; then
                echo "Sent email for log entry: $line"
            else
                echo "Failed to send email for log entry: $line"
            fi
        done
    fi

    # Update last_lines for the next iteration
    last_lines=$current_lines

    # Wait before checking again
    sleep $CHECK_INTERVAL
done

5. Run both as a service

vi /etc/init.d/honeypot_service
#!/bin/sh /etc/rc.common

START=99
STOP=10

USE_PROCD=1

start_service() {
    procd_open_instance
    procd_set_param command /bin/sh /root/smtp-alerts-monitor.sh
    procd_set_param respawn
    procd_close_instance

    procd_open_instance
    procd_set_param command /bin/sh /root/start-honeypot.sh
    procd_set_param respawn
    procd_close_instance
}

stop_service() {
    killall -9 socat 2>/dev/null
    rm -rf /tmp/honeypot/
}
chmod +x /etc/init.d/honeypot_service
/etc/init.d/honeypot_service enable
/etc/init.d/honeypot_service start

Automatic lockdown mode

When a single IP keeps triggering listeners, the router quarantines it automatically instead of flooding my inbox.

MAC block: the block_mac function adds an ebtables rule that drops all traffic from the offending MAC:

  • Command: ebtables -A FORWARD -s <MAC_UPPER> -j DROP
  • Effect: drops every packet in the FORWARD chain from that MAC, preventing the device from communicating through the router or reaching other LAN devices.

nft rules: when a lockdown initiates, the add_lockdown_rule function:

  • Creates an nft table named honeypot_lockdown_<IP> (e.g. honeypot_lockdown_192_168_1_248).
  • Adds a prerouting chain with an nat hook, priority 0, and accept policy.
  • Adds rules to redirect TCP traffic: the same ports stay open, but all traffic is redirected to port 6969. That keeps the attacker in the dark without spamming me with email alerts, and the redirects are logged.
nft add table ip honeypot_lockdown_<IP>
nft add chain ip honeypot_lockdown_<IP> prerouting "{ type nat hook prerouting priority 0; policy accept; }"
nft add rule ip honeypot_lockdown_<IP> prerouting ip saddr <IP> ip daddr 192.168.1.0/24 tcp dport <port> redirect to :6969

Tracker file: keeps track of epoch timestamps to determine lockdown duration:

  • If the number of logged connections within WINDOW_DURATION reaches CONNECTION_THRESHOLD, the lockdown initiates.
  • The last_line field tracks which log line was last processed for a given IP, so duplicate/old entries aren’t reprocessed.
root@openwrt:~# cat /tmp/honeypot/ip_tracker
1751656185 192.168.1.248 3 69
